# ListenWise 项目复盘（2026-06-10）

> 来源：5 份静态代码审查 + 3 份真机走查（真机走查因本地后端未启动，实际均退化为静态分析）。
> 本报告做了去重、严重度校准、剔除证据不足项。每条均带文件:行号或代码/文案引用。

## 一、总体评价

整体看，ListenWise 三条核心旅程（会议录音 / 本地上传 / 播客）的后端链路和数据模型设计扎实，M9 设计系统落地完整（蓝紫色残留已彻底清除、token 化到位），okPoints 数量可观，说明地基稳。但前端「上传/录音 → 转写 → 看结果」这条最高频用户路径上存在多个真实断点：转写完成后页面不会自刷新、上传成功后被甩回首页、失败状态无任何提示和重试入口、播客转写完成后无法进入完整分析页。这些不是边角问题，而是会让普通用户在主流程上「卡住、困惑、或丢数据」。术语层面「转写/转录」「逐字稿/文字稿」「录音/实时记录」三组词多轨并行，加重认知负担。建议先集中修复 6 个 P0 打通主链路，再统一术语和补齐失败态/导航。

| 严重度 | 数量 | 说明 |
|---|---|---|
| P0 | 6 | 功能断点 / 数据丢失风险 |
| P1 | 14 | 明显不一致 / 误导用户 / 异常无反馈 |
| P2 | 18 | 打磨项 |

注：另有「本地后端未启动导致 PasscodeGate 死锁」「生产 summary_model 实际值未核实」两项不计入产品缺陷计数，分别归入第五节（环境问题）和第六节末（待验证）。
