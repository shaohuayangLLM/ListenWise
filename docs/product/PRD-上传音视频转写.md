## 1. 背景与目标

| 维度 | 说明 |
|------|------|
| 现状痛点 | 用户有大量音视频素材（网课、会议录音、访谈），需要转成可读、可搜、可编辑的文字稿；现有工具要么只给一段裸文本、要么把模型能力锁死在单一厂商、要么贵。 |
| 目标 | 提供「上传音视频 → 自动转写为带说话人和时间戳的逐字稿 → 编辑/总结/导出」的完整闭环；AI 能力走可配置的公有云 API，成本与厂商可控。 |
| 首期范围（In Scope） | 模型设置（Provider 配置）、音视频上传与前置校验、视频自动提取音轨、转写、逐字稿查看（音字联动）、逐字稿编辑、说话人重命名/重识别、手动 AI 总结、导出（粒度可配）。 |
| 不做（Out of Scope） | 播客链接转写（P1）、实时转录（P2）、多人协作/评论/分享权限、商业化分层、自定义术语表/热词、片段 clip、AI 问答。 |
| P1 后续 | 多文件上传队列（本期可选，见 F2.4）、词级时间戳高亮、编辑历史版本。 |

### 成功指标（可量化）

| # | 指标 | 目标 |
|---|------|------|
| S1 | 转写任务成功率（排除用户文件本身损坏/无音轨） | ≥ 95% |
| S2 | 1 小时时长音频，从上传完成到逐字稿可见 | < 5 分钟 |
| S3 | 不合规文件（格式/大小/时长/音质）在上传阶段被拦截并给出明确原因 | 100% |
| S4 | 点击逐字稿任意段落，音频定位到该段起点（段级精度） | 偏差 < 0.5s |

## 2. 用户故事与场景

### 2.1 角色

| 角色 | 描述 | MVP 范围 |
|------|------|---------|
| 单用户 | 个人知识工作者，自己上传、查看、管理转写 | 单用户，user_id 硬编码；多用户/权限放后续 |

### 2.2 用户故事

- US1：作为用户，我想上传一段会议录音，自动转成带说话人区分的逐字稿，这样我不用从头听一遍。
- US2：作为用户，我想上传一节网课视频，系统自动提取音轨并转写，这样我能把视频内容变成可搜索的文字。
- US3：作为用户，我想把转写里的「说话人 A」改成真实姓名，并修正个别识别错的字，这样逐字稿能直接用。
- US4：作为用户，我想对长录音一键生成摘要要点，这样我能快速回顾，而不必每次都读全文。
- US5：作为用户，我想把逐字稿导出成字幕（SRT/VTT）或文档（Markdown），并能选择要不要带说话人和时间戳。
- US6：作为用户，我想在设置里填我自己的转写/大模型服务密钥，用我自己的账号和额度。

### 2.3 典型场景

| 场景 | 描述 |
|------|------|
| 会议录音转写 | 上传 1 小时多人会议 m4a → 转写出带 A/B/C 说话人的逐字稿 → 重命名说话人 → 生成摘要 → 导出 Markdown |
| 网课视频转写 | 上传 mp4 网课 → 自动提取音轨 → 转写 → 边播边读、点句子跳转 → 导出 SRT 做字幕 |
| 访谈整理 | 上传访谈录音 → 转写 → 修正专有名词 → 导出纯文本（不含时间戳）交付 |

## 3. 流程与状态

### 3.1 用户操作主流程

```
进入设置页配置 ASR/LLM 服务密钥（首次）
      ↓
上传页：选择音视频文件 → 填标题/备注 → 提交
      ↓
[上传校验] 格式/大小/时长/音质 → 不合规即时拦截并提示原因
      ↓
后台处理：视频自动提取音轨 → 提交转写 → 识别
      ↓
列表/详情页：查看转写进度
      ↓
转写完成 → 逐字稿查看（音字联动播放）
      ↓
可选操作：编辑文本 / 重命名说话人 / 重新识别 / 生成摘要 / 导出
```

### 3.2 任务状态机

| 状态 | 含义 | 进入条件 |
|------|------|---------|
| uploading | 文件上传中（前端 → 服务端） | 用户提交上传 |
| processing | 后台预处理：视频提取音轨（纯音频自动跳过）、提交转写 | 上传校验通过 |
| transcribing | 识别进行中 | 预处理完成 |
| done | 转写完成，逐字稿可用 | 识别成功落库 |
| failed | 失败（任一环节出错） | 处理/识别异常 |

> 状态流：`uploading → processing → transcribing → done`，任一环节出错 → `failed`；`failed` 点「重试」→ 回到 `processing` 重新处理（复用已上传文件，不重新上传）。
> 说明：`processing` 为本期新增状态（现有仅 uploading/transcribing/done/failed）。新增 processing 后，**四处需同步纳入该状态**：进度轮询查询集合、进度百分比映射、记录列表的状态标签、处理中任务统计（详见 §8.3）。

### 3.3 操作与状态关联矩阵

| 状态 | 可用操作 |
|------|---------|
| uploading | 取消上传 |
| processing | 等待（取消为 P1） |
| transcribing | 等待（取消为 P1） |
| done | 查看、编辑逐字稿、重命名说话人、重新识别(P1)、生成摘要、导出、删除 |
| failed | 查看失败原因、重试、删除 |

### 3.4 操作行为说明

| 操作 | 行为 |
|------|------|
| 重新识别 | 用当前 ASR 配置重新转写该文件，覆盖原逐字稿；若已编辑过，先二次确认 |
| 重试 | 从失败点重新走预处理+识别，不重新上传文件 |
| 生成摘要 | 手动触发，调用 LLM 对全文生成摘要要点；逐字稿字数 < 250 时按钮禁用 |
| 删除 | 二次确认后，删除记录与关联逐字稿、本地文件，不可恢复 |

## 4. 功能需求

### F0 模型设置（Provider 配置 · 前置依赖）【新增】

按能力维度独立配置公有云 API（决策 D1）。P0 涉及 **ASR** 与 **LLM 总结** 两类（翻译属 P2）。

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| F0.1 | ASR 服务配置 | P0 | 选择 Provider（首发百炼 Fun-ASR）、填写密钥、模型名；保存后用于所有转写 |
| F0.2 | LLM 服务配置 | P0 | 选择 Provider（首发 qwen）、填写密钥、模型名；用于 AI 总结 |
| F0.3 | 密钥安全存储 | P0 | 密钥加密存储，页面回显时脱敏（只显示后 4 位） |
| F0.4 | 连接测试 | P0 | 保存时做一次轻量探活验证密钥有效；否则密钥错误要到转写阶段才暴露（反馈链路长、失败成本高） |
| F0.5 | 未配置兜底 | P0 | 开发态（debug）未配置 ASR → 走 mock 数据、不拦截；生产态未配置 → 上传入口拦截并提示去配置 |

**校验规则**：

| 校验项 | 提示文案 |
|--------|---------|
| ASR 密钥为空就上传（生产态） | "尚未配置转写服务，请先到设置页填写密钥"；开发态走 mock 不拦截 |
| 密钥格式明显非法 | "密钥格式不正确，请检查后重试" |

### F2 上传前置校验【改造 + 新增】

| 编号 | 功能 | 优先级 | 现状 |
|------|------|--------|------|
| F2.1 | 格式白名单校验（音频 + 视频） | P0 | 【复用】扩展名校验已有 |
| F2.2 | 文件大小校验：音频 ≤500MB、视频 ≤6GB | P0 | 【改造】现统一 500MB；需前后端双处常量分档，且 6GB 上传涉及超时/稳定性，非简单调参 |
| F2.3 | 时长校验 ≤6 小时 | P0 | 【新增】上传时检测时长 |
| F2.4 | 音质校验：采样率 ≥16kHz | P0 | 【新增】上传时检测采样率，过低提示 |
| F2.5 | 多文件上传队列 | P1 | 【新增】一次选多个、逐个处理、进度可视 |

**校验分层**（解决「即时拦截」与「需读文件元数据」的矛盾）：

- **同步拦截层**（格式 F2.1 / 大小 F2.2 / 空文件）：前端 + 上传入口即时校验，不合规直接拒绝、不创建记录。
- **元数据探测层**（时长 F2.3 / 采样率 F2.4）：需读取文件元数据，在文件暂存后探测；时长超限则拒绝并清理暂存文件，采样率过低为提示可继续（见 A2）。
- 现有上传流程是「先建记录再存文件」，需调整为「先暂存探测、通过才正式建记录」，避免产生无效记录。

**校验规则**：

| 校验项 | 提示文案 |
|--------|---------|
| 格式不支持 | "不支持该格式，请上传 MP3 / WAV / M4A / MP4 等音视频文件" |
| 音频超 500MB | "音频文件超过 500MB 上限" |
| 视频超 6GB | "视频文件超过 6GB 上限" |
| 时长超 6h | "文件时长超过 6 小时上限" |
| 采样率过低 | "音频采样率过低（建议 ≥16kHz），转写质量可能不佳" |
| 空文件 | "文件为空，请重新选择" |

## 6. 非功能需求

### 6.1 性能 / 可靠性

| 维度 | 要求 |
|------|------|
| 转写时延 | 1 小时音频端到端 < 5 分钟（异步，依赖 provider） |
| 上传 | 6GB 视频上传过程显示实时进度，不阻塞页面 |
| 并发 | 后台转写按 worker 并发处理，任务排队不丢失 |
| 失败可恢复 | 转写失败可重试，不需重新上传文件 |

### 6.2 边界场景（≥10）

| # | 场景 | 预期行为 |
|---|------|---------|
| B1 | 上传加密/损坏文件 | 转写失败，提示"文件无法解析" |
| B2 | 上传 0 字节空文件 | 上传前拦截，提示"文件为空" |
| B3 | 音频超 500MB / 视频超 6GB | 上传前拦截，提示超限 |
| B4 | 文件时长超 6 小时 | 上传前拦截，提示"时长超 6 小时上限" |
| B5 | 采样率 < 16kHz | 提示音质偏低，可继续但标注风险 |
| B6 | 视频无音轨 | 提取音轨失败，标记 failed，提示"未检测到音轨" |
| B7 | 纯静音/无人声音频 | 转写结果为空，提示"未识别到语音内容" |
| B8 | 多人同时说话/串台 | 说话人分离可能不准，允许手动纠正与重命名 |
| B9 | 未配置 ASR 就上传 | 提示先去设置页配置（开发态走 mock） |
| B10 | 逐字稿字数 < 250 点生成摘要 | 按钮禁用 + 提示字数不足 |
| B11 | 转写中网络中断/服务超时 | 标记 failed，可重试 |
| B12 | 快速双击上传/提交按钮 | 首次点击后按钮禁用，防重复提交 |
| B13 | 同名文件多次上传 | 各自独立记录，不去重 |
| B14 | 重新识别覆盖已编辑内容 | 二次确认后才覆盖 |
| B15 | 导出时说话人/时间戳都不勾 | 输出纯文本（仅内容） |
| B16 | 删除记录 | 弹确认弹窗「将永久删除记录与逐字稿，不可恢复」，确认后才执行 |

### 6.3 风险评估

| 风险 | 等级 | 影响 | 应对 |
|------|------|------|------|
| Fun-ASR 中文/说话人分离效果不达预期 | 中 | 逐字稿质量差、分人乱 | 上线前实测；保留 DashScope 作备选 provider；说话人允许手动纠正 |
| 视频抽音轨对超大文件耗时长/占磁盘 | 中 | 处理慢、磁盘压力 | 抽完即删原视频；大文件给处理中提示 |
| 采样率校验过严误拦合法录音 | 中 | 正常文件被拒 | 改为「提示+可继续」而非硬拦（见 B5） |
| 密钥泄露 | 高 | 用户云账号被盗刷 | 加密存储、脱敏回显、不写日志 |

**三种攻击角度自检**：

| 攻击角度 | 问题与回答 |
|---------|-----------|
| 依赖失效 | ASR provider（百炼）API 挂了怎么办？→ 退化路径：① 切换备用 provider（DashScope）；② 任务保持排队并定时重试；③ 开发态回落 mock。不依赖单一厂商存活。 |
| 规模爆炸 | 上传/转写量到 10x（如批量几十个长视频并发）哪一步先崩？→ 后台转写 worker 队列先堆积，转写时延拉长。应对：worker 并发数可配 + 队列长度告警 + 单用户同时进行中的任务数限流。 |
| 回滚成本 | Provider 配置体系若方向错？→ 数据可逆（配置表可清空、source 字段有默认值）；UI 可下线（设置页可隐藏，回落单一 provider）；无商务承诺，回滚成本低。 |

## 8. 附录

### 8.1 术语表

| 术语 | 含义 |
|------|------|
| Provider | 提供某项 AI 能力的公有云服务（如百炼、DashScope、qwen） |
| ASR | 语音识别，音频转文字 |
| 逐字稿 / segments | 按段的转写结果，每段含起止时间、说话人、文本 |
| 音字联动 | 逐字稿与音频播放进度同步：高亮当前段、点击段落跳转音频 |
| 说话人分离 | 自动区分录音中不同发言人（标记 A/B/C…） |
| 抽音轨 | 从视频文件提取音频，用于转写 |

### 8.3 数据模型影响（供技术设计参考）

> PRD 不定技术实现，此处仅列需求驱动的数据变化，细节进技术设计文档。

- Recording 新增 `source` 字段（`upload | podcast | realtime`）：upload 接口写入 `source='upload'`；历史行迁移默认 `upload`；与 legacy `scene_type` 并存（scene_type 不再使用）。
- 新增 `processing` 状态后，进度轮询查询集合、进度百分比映射、列表状态标签、处理中任务统计四处需同步纳入。
- 新增「模型配置」存储：按能力维度（asr/llm）保存 provider、加密密钥、endpoint、模型名、启用状态。
- Transcript 扩展：说话人显示名映射（重命名）、是否已编辑标记、摘要内容及生成模型。
- 状态枚举新增 `processing`（现有 uploading/transcribing/done/failed，`analyzing` 为 legacy）。
- 现有 `scene_type` / `folders` / `tags` 为 legacy，不在本期使用。
