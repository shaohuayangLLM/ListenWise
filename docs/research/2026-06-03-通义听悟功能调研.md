## 二、专题：链接导入 / 在线转写能力（对 ListenWise 播客功能最相关）

**结论：通义听悟的「在线链接转写」能力是受限的，只对播客 RSS 开放，对视频平台直链关闭。**

- **支持**：播客 **RSS 链接**导入转写。即用户拿到播客节目的 RSS feed 地址，输入听悟即可转写。
- **不支持直链解析**：优酷、抖音、爱奇艺、腾讯视频、哔哩哔哩等平台链接**无法直接解析**，官方明确为「服务条款限制」，引导用户下载后再上传。
- **小宇宙 / Apple Podcasts / Spotify**：官方帮助页（登录墙，未取到原文）未确认是否直接支持单集页面链接；社区实践（即刻/少数派）通常是「找到播客的 RSS 源 → 喂给听悟」，而非粘贴单集网页链接（未确认官方是否做了平台适配）。
- **浏览器插件是另一条在线路径**：Chrome/Edge 扩展可在网页播放在线音视频时直接抓取转写，绕开「链接解析」限制——这对 ListenWise 是一个值得借鉴的工程取巧点。

> 对 ListenWise 的提示：通义听悟把「在线视频平台直链」当成法务/版权红线主动回避，只走 RSS 这种开放协议。这解释了为什么播客（开放 RSS 生态）是它唯一开放的「链接转写」入口。

## 三、专题：通义听悟 / 阿里云 ASR API 能力与计费（ListenWise 走公有云 API 的选型依据）

ListenWise 若全走公有云 API，有两条阿里系路线：**(A) 通义听悟开放 API**（带 AI 总结的「全家桶」）和 **(B) 阿里云百炼录音文件识别 / 实时识别 API**（裸 ASR，自己做后处理）。

### A. 通义听悟开放 API（含 AI 能力，按能力叠加计费）

- 提供：文件离线转写、实时记录（创建/推流/结束）、说话人区分、热词、时间戳，以及大模型摘要/速览/PPT 等。
- 计费按「实际调用到的能力」独立计时、**叠加**：

| 能力 | 单价（元/小时） |
|---|---|
| ASR 转写（实时 + 文件） | 0.6 |
| 大模型基础能力（摘要/章节速览/发言总结/关键词等） | 0.064 |
| 质检 / 对话提取 | 0.13 |
| 多模态 PPT 提取 | 0.64 |
| 实时翻译 | 4 |
| 离线翻译 | 0.5 |

- 叠加示例：1 小时实时记录 + 实时翻译 = 0.6 + 4 = 4.6 元；中英双语翻译费用翻倍。
- 旧版接口为按日梯度计费（实时 10.5 元/时起、文件 9.5 元/时起、翻译 8 元/时起），新项目应用新版按能力计费。

### B. 阿里云百炼 录音文件识别 / 语音识别 API（裸 ASR）

**模型矩阵：**

| 模型 | 类型 | 最长时长 | 最大文件 | 说话人分离 | 时间戳 | 热词 | 情感识别 |
|---|---|---|---|---|---|---|---|
| Fun-ASR | 异步文件 | 12h | 2GB | ✓ | 句级(固定)+词级 | ✓ | ✗ |
| Paraformer | 异步文件 | 12h | 2GB | ✓ | 句级(可配) | ✓ | ✗ |
| Qwen3-ASR-Flash-Filetrans | 异步文件 | 12h | 2GB | ✗ | 句级+词级(固定) | ✗ | ✓ |
| Qwen3-ASR-Flash | 同步/流式 | 5min | 10MB | ✗ | ✗ | ✗ | ✓ |

- **说话人分离**：仅 Fun-ASR 系列（fun-asr、fun-asr-mtl）非实时模型支持；启用时建议音频 ≤2 小时。
- **实时识别**：基于 WebSocket，流式输入/输出，适合实时字幕/会议转写；fun-asr-realtime 支持实时热词。
- **输入方式**：公网音频 URL（所有模型）、Base64、本地路径（限 100 QPS、不建议生产）。
- **格式**：aac/wav/mp3 等主流音视频格式，采样率不限。
- **部署区域**：中国（北京）、国际（新加坡）、美国（弗吉尼亚，仅 Qwen3-ASR-Flash-us）。
- **计费**：Paraformer 录音文件识别约 **0.00008 元/秒 ≈ 0.288 元/小时**（资源包耗尽后约 0.6 元/小时）。Fun-ASR / 说话人分离的单独加价项官方价目页未单列（未确认，建议在百炼模型定价页核对最新值）。

### 选型小结（A vs B）
- 要「转写 + 摘要/导图/问答」一站式 → 走 **A 通义听悟 API**，省自研但单价高、翻译尤其贵（4 元/时）。
- 要「便宜、可控、自己做 AI 后处理」→ 走 **B 百炼裸 ASR**（Paraformer ~0.288 元/时最便宜，Fun-ASR 给说话人分离），摘要用通义千问/自选 LLM 单独调，成本与体验自己拼。
- ListenWise 若强调播客长音频 + 说话人 + 自研卡片式总结，**B 路线（Fun-ASR 文件转写 + 自研 LLM 总结）性价比更高**；实时转录则用 fun-asr-realtime。

## 四、对 ListenWise 三大功能的可借鉴点

### 功能一：上传音视频转写
- **格式/限制抄作业**：音频单文件 500MB、视频 6GB、时长 6 小时、采样率 ≥16k——这是经过验证的体验/成本平衡点，ListenWise 可直接对齐或略放宽。
- **批量队列**：听悟做了「最多 50 个并发转写」。ListenWise 上传区应支持多文件队列 + 进度可视，而非单文件阻塞。
- **采样率前置校验**：低于 16k 直接拒绝并提示，避免低质音频浪费转写费——在上传环节就做 ffprobe 校验。
- **AI 能力分层、按需触发**：听悟把摘要/速览/导图/待办/QA 设了字数门槛（如 ≥250 字才出摘要、待办最多 6 条）。ListenWise 应同样按内容长度分级触发，短音频不硬塞导图，省 token 也避免「空洞输出」。

### 功能二：播客链接转写
- **以 RSS 为一等公民**：听悟在视频平台直链上主动设限，唯独开放 RSS。ListenWise 播客功能应**以 RSS 解析为核心**（订阅源 → 单集 enclosure 音频 URL → 走 ASR），这是法务最干净、最稳的路径。
- **避开平台直链解析的法务雷区**：不要做 B站/YouTube 直链下载转写（听悟明确回避）。若要支持小宇宙/Apple/Spotify，优先走它们的 RSS / 公开音频地址，而非爬页面。
- **浏览器插件作为补充入口**：听悟用扩展抓「正在播放的在线音视频」绕过链接解析限制——ListenWise 若想覆盖无 RSS 的内容，插件是合规的替代方案。
- **后端实现**：拿到 RSS enclosure 的公网音频 URL 后，直接喂百炼 Fun-ASR（支持 URL 输入 + 说话人分离 + 12h/2GB），无需先落盘，链路最短。

### 功能三：实时转录
- **边录边转 + 实时翻译分开计费意识**：听悟实时翻译单价高达 4 元/时（是转写的近 7 倍）。ListenWise 实时翻译应做成**可选开关**而非默认开启，并在 UI 上让用户感知这是高成本能力。
- **多路并发/多声道**：听悟实时支持最多三路声道、免费 2 路并发。ListenWise 实时场景（会议/访谈）要规划声道与并发模型，单路 mic 与多路混音体验不同。
- **实时 ASR 选型**：走百炼 fun-asr-realtime（WebSocket 流式 + 实时热词），热词对专有名词/人名识别提升明显，应开放给用户自定义术语表。
- **字幕形态可切换**：听悟做了多字幕形态。ListenWise 实时界面至少提供「滚动逐字稿 / 当前句大字幕」两种视图，照顾「会议记录」与「演讲字幕」两类用途。
