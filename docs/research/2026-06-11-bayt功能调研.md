# Bayt 客户端功能调研报告

> 调研目的：为 ListenWise 播客订阅、单集文字稿、双语转录、Obsidian 导出等需求提供产品参考。
> 调研时间：2026-06-11。信息来源为本机已安装 Bayt macOS 客户端实操观察，未做网络资料补充；会员、后端生成策略、完整付费链路未验证。

## 一、整体定位

Bayt 不是纯粹的「播客文字稿管理工具」，更像一个面向中文用户的「全球播客/文章中文化消费工具」。

它的核心体验不是上传文件后得到一份稿件，而是：

```text
发现全球播客/文章 → 选择单集 → 生成中文音频和字幕 → 双语字幕/简介辅助收听
```

因此，Bayt 更偏内容消费和语言转换，ListenWise 当前更偏「转写、文字稿、归档、导出」的生产力工具。两者可以借鉴交互和信息架构，但不建议照搬播放、声音克隆、中文音频生成这条主线。

## 二、信息架构

Bayt 顶部主导航为四个一级入口：

| 入口 | 功能定位 | 观察到的主要内容 |
|---|---|---|
| 首页 | 内容流 / 推荐消费 | 热门、往期精选、科技与商业、早报、中国、日本、韩国等频道 |
| 发现 | 播客发现 / 搜索 / 策展目录 | 搜索播客、声音克隆专区、硅谷热门、投资者专区、女性专区、语言初学者、儿童专区、分类热门、国家热门 |
| 关注 | 已关注节目更新 | 最近更新、关注列表；空态引导去发现 |
| 个人 | 会员、记录、收藏、缓存、设置 | 免费额度、升级会员、历史记录、我的收藏、离线缓存、分享、联系、用户群、设置 |

页面整体是移动端产品移植到桌面端的形态：顶部居中分段导航，内容区窄栏，底部保留迷你播放器。

## 三、核心功能拆解

### 1. 首页：内容消费优先

首页展示的是可直接消费的单集内容，而不是用户自己的文件或订阅管理。

观察到的内容形态：

- 顶部频道：热门、往期精选、科技与商业、早报、中国、日本、韩国。
- 左侧主列表：封面、节目名、标签（如「精选」「免费」）、中文标题、时长。
- 右侧/次级榜单：最热门、最新、分类等。
- 部分内容直接标「免费」，用于冷启动和体验转化。

对 ListenWise 的启发：如果要做播客场景，用户不一定从 RSS 开始，很多时候是从「我想找某个节目/某个话题」开始。搜索和发现能力比单纯粘贴 RSS 更自然。

### 2. 发现页：节目目录和策展

发现页是 Bayt 最值得参考的一块。

它把节目发现拆成多个维度：

- 搜索入口：占据页面顶部，placeholder 为「搜索播客...」。
- 策展专区：例如声音克隆专区、硅谷热门、投资者专区、女性专区、语言初学者、儿童专区。
- 分类热门：科技、新闻、健康、历史、商业、教育、艺术、喜剧、科学、小说、音乐、社会与文化、体育、真实犯罪、电视与电影。
- 国家热门：美国、日本、韩国、中国、英国、西班牙、法国、德国、意大利、泰国、越南、巴西、加拿大、澳大利亚、墨西哥、俄国、荷兰、瑞典、挪威、新西兰、印度。
- 节目卡片：封面、节目名、简短描述、右侧关注按钮。

这说明 Bayt 把「播客搜索」做成了产品入口，而不是配置入口。ListenWise 的播客功能也应避免只让用户输入 RSS 地址。

### 3. 搜索：节目和单集分层

实测搜索 `lenny` 后，结果分为两组：

- 节目：展示节目封面/名称，右侧可以直接关注。
- 单集：展示单集标题、所属节目、发布日期、时长，右侧提供播放入口。

这个结构非常适合 ListenWise：

```text
搜索结果
├── 节目：进入节目详情 / 手动订阅
├── 单集：进入单集详情 / 只获取这一集文字稿
└── YouTube：进入视频详情 / 获取文字稿
```

注意：本次搜索 `lenny` 首屏节目命中并不完全准确，先出现了非目标的 `LENNY` 节目，真正的 `Lenny's Podcast: Product | Career | Growth` 在发现页策展区能准确进入。这说明搜索召回和排序很关键，尤其是国外播客名称相近、重名较多。

### 4. 节目详情页：先判断价值，再处理单集

节目详情页结构：

- 顶部：返回、搜索、转发、喜欢。
- 节目头部：封面、节目名、作者、简介入口。
- 单集 tab：全部、最热门、筛选排序。
- 单集列表：封面、标题、shownotes 摘要、日期、时长、更多菜单。
- 右侧有「翻译」入口。

Bayt 的节目页没有把列表做成纯标题清单，而是直接展示 shownotes 摘要。这点很关键：用户在决定要不要处理一集之前，需要先知道这集讲什么。

对 ListenWise 的直接建议：

- 节目详情页的单集列表必须展示 shownotes 摘要。
- 每集要显示状态：未获取文字稿、转写中、已完成、失败、已导出。
- 支持批量选择未转写单集，再批量获取文字稿。
- 筛选条件建议先做：全部、未转写、已完成、最近发布、最热门（如数据可得）。

### 5. 单集详情页：播放器很重，但稿件结构可借鉴

Bayt 单集详情是强播放器形态：

- 大封面和沉浸式背景。
- 进度条、倍速、后退/前进 15 秒、播放/暂停。
- 顶部收藏、分享、更多。
- 主 CTA：「生成中文音频和字幕」。
- 生成/加载后出现字幕区。

Bayt 的字幕区支持：

- 原文 / 中文切换。
- 当前字幕段展示中文与英文双语。
- 简介区展示 shownotes。
- 完整简介以浮层形式展开。
- 全屏字幕入口。

ListenWise 已明确「不做播放，只做播客单集文字稿」，因此不建议照搬播放器。但可以借鉴稿件组织：

```text
单集详情
├── 文字稿
│   ├── 原文
│   ├── 中文
│   └── 双语对照
├── Shownotes
├── AI 解读
└── 元信息
```

其中 `Shownotes` 应默认保留节目源内容，`文字稿` 是用户手动获取后出现，`AI 解读` 是可选增强。

### 6. 更多菜单：围绕单集和节目关系

Bayt 单集更多菜单包含：

- 收藏本集
- 关注节目
- 查看节目
- 下载
- 双语交替播放
- 交替顺序
- 反馈问题

可借鉴的不是「双语播放」本身，而是操作分层：

- 单集动作：收藏、下载、反馈。
- 节目动作：关注节目、查看节目。
- 双语动作：语言顺序、原文/中文视图。

ListenWise 对应可以设计为：

- 获取文字稿
- 重新转写
- 导出 Obsidian
- 复制 Markdown
- 下载 Markdown / TXT / SRT / VTT
- 查看原始链接
- 查看节目
- 反馈问题

结合用户反馈，「我的记录」里的常用操作应该直接外露，不应全部藏到三点菜单。

### 7. 关注页：最近更新和关注列表

关注页分为：

- 最近更新
- 关注列表

未关注任何节目时，空态文案是「你还没有关注任何播客」，并提供「去发现」按钮。

这对 ListenWise 很适合：播客订阅不是自动定时同步，而是用户手动获取最新订阅。关注页可以默认展示订阅节目的最近更新，让用户手动选择哪些新集要转写。

建议结构：

```text
播客
├── 最近更新：所有订阅节目的新单集
├── 订阅节目：节目列表
└── 全部单集：跨节目单集库
```

### 8. 历史、收藏、离线缓存

个人页提供：

- 历史记录：展示打开/听过的单集，包含封面、标题、剩余时长、更多菜单。
- 我的收藏。
- 离线缓存。

Bayt 的历史记录围绕「继续听」设计，ListenWise 的记录应围绕「继续处理/继续阅读」设计。

可迁移为：

- 最近处理：转写中、失败、待导出、最近完成。
- 收藏：重要文字稿。
- 导出记录：最近导出到 Obsidian / 下载的稿件。

### 9. 设置：字幕和文本翻译

设置页包含：

- 使用情况。
- 在播放页和字幕页中保持屏幕常亮。
- 字体大小：跟随系统。
- 文本翻译与朗读。
- 关于 Bayt。
- 退出登录、删除账号。

「文本翻译与朗读」页支持粘贴外文或中文短文，或直接输入网页链接，然后生成中文音频。

这说明 Bayt 把「文本/网页链接 → 中文音频」也纳入同一套生成模型。ListenWise 不必做音频生成，但可以借鉴「网页链接/YouTube/播客链接统一识别」的输入框设计。

## 四、商业模式观察

个人页展示：

- 免费版：畅听首页免费内容，每月另可生成一次其他内容。
- 本月剩余次数：0 次。
- 重置日期：7月11日。
- 高级会员：每月 80 小时中文音频生成。

Bayt 的付费墙围绕「中文音频生成时长/次数」，而不是单纯文字稿。

对 ListenWise 的启发：

- 如果后续做商业化，额度提示要靠近高成本动作，例如转写、翻译、AI 解读。
- 但不要照搬「中文音频生成」会员叙事，ListenWise 更适合强调「转写分钟数」「播客单集文字稿」「AI 解读次数」「Obsidian/知识库导出」。

## 五、对 ListenWise 的可借鉴清单

### 高优先级

1. **播客搜索升级**
   - 支持节目、单集、YouTube 分组。
   - 支持国外 podcast、中文 podcast、小宇宙、RSS。
   - 搜索结果不默认订阅，用户手动订阅或只处理单集。

2. **搜索结果可进入节目详情**
   - 节目结果进入节目详情页。
   - 单集结果进入单集详情页。
   - 节目详情页再提供订阅按钮。

3. **单集详情多 tab**
   - 文字稿、Shownotes、AI 解读、元信息。
   - 文字稿支持原文、中文、双语对照。

4. **节目详情展示 shownotes 摘要**
   - 不要只显示标题列表。
   - 用户应在转写前判断该集是否值得处理。

5. **批量选择单集**
   - 在节目详情页支持多选。
   - 批量获取文字稿。
   - 对已完成/转写中/失败状态做禁用或提示。

6. **操作按钮外露**
   - 我的记录和录音详情页中，常用操作直接展示。
   - 导出 Obsidian 应成为一等操作，不藏在更多菜单里。

### 中优先级

7. **最近更新视图**
   - 聚合所有订阅节目的新集。
   - 用户手动点击「获取最新订阅」后更新。

8. **当前任务条**
   - 借鉴 Bayt 迷你播放器，但改成转写任务条。
   - 展示当前转写单集、状态、进入详情、重试/取消。

9. **双语稿件导出**
   - Markdown 导出支持原文、中文、双语。
   - Obsidian 导出把双语稿、shownotes、AI 解读分节写入。

10. **完整简介/Shownotes 浮层或展开**
    - 列表里显示摘要。
    - 详情里可展开完整 shownotes。

### 低优先级或暂缓

11. 收藏、历史、离线缓存可以后置。
12. 分类/国家热门可以作为推荐能力后置。
13. 文本/网页链接转中文音频不符合当前产品主线，暂不做。

## 六、不建议照搬的点

1. **不做播放主流程**
   - 用户已经明确 ListenWise 不做播放。
   - 播放器会显著增加音频状态、缓存、进度、移动端适配复杂度。

2. **不做声音克隆**
   - Bayt 的声音克隆专区是内容消费卖点。
   - ListenWise 当前的价值是文字稿和知识沉淀，不应引入高风险音频合成链路。

3. **不做中文音频生成**
   - 这会把产品从转写工具变成 TTS 内容消费工具。
   - 成本、版权、用户预期都会改变。

4. **不把首页改成内容 feed**
   - Bayt 首页适合内容消费。
   - ListenWise 首页更适合工作台：最近记录、转写任务、订阅更新、导出状态。

## 七、建议落地到 PRD 的功能结构

### 播客搜索

```text
输入：关键词 / RSS URL / 小宇宙节目主页 / Apple Podcasts / YouTube URL

结果：
- 节目
  - 封面、节目名、作者、简介、来源
  - 操作：查看详情、订阅
- 单集
  - 标题、节目名、日期、时长、shownotes 摘要
  - 操作：查看详情、获取文字稿
- YouTube
  - 标题、频道、发布时间、时长
  - 操作：查看详情、获取文字稿
```

### 节目详情

```text
节目头部：
- 封面、节目名、作者、简介、来源链接
- 订阅/取消订阅
- 手动刷新此节目

单集列表：
- 多选 checkbox
- 标题、发布时间、时长、shownotes 摘要
- 状态：未获取 / 转写中 / 已完成 / 失败
- 操作：获取文字稿、查看详情、导出

批量操作：
- 批量获取文字稿
- 批量导出 Obsidian（仅已完成）
```

### 单集详情

```text
顶部：
- 节目名、单集标题、发布日期、时长、原始链接
- 获取/重新获取文字稿
- 导出 Obsidian

Tabs：
- 文字稿：原文 / 中文 / 双语对照
- Shownotes：源站 shownotes，保留原始链接
- AI 解读：摘要、要点、关键词、可选
- 元信息：RSS URL、episode URL、audio URL、source、导出记录
```

### Obsidian 导出

导出 Markdown 建议包含：

```markdown
---
type: podcast_episode
podcast: 节目名
episode: 单集标题
source_url: 原始播客链接
audio_url: 音频链接
published_at: 发布日期
duration: 时长
transcript_language: 原文/中文/双语
generated_by: ListenWise
---

# 单集标题

## 元信息

## Shownotes

## AI 解读

## 文字稿
```

## 八、边界情况

1. **搜索误召回**
   - 国外播客重名多，搜索排序要优先官方节目、订阅数/最近更新/来源可信度。

2. **Shownotes 为空或 HTML 很脏**
   - 需要 HTML 清洗、链接保留、纯文本降级。

3. **同一单集来自多个来源**
   - Apple Podcasts、RSS、小宇宙、YouTube 可能重复，需要去重策略。

4. **YouTube 与播客的元信息不同**
   - YouTube 没有 RSS shownotes，需要映射为 description。

5. **双语文字稿不是总能得到**
   - 原文转写、翻译稿、双语对照应是三个独立状态，不能假设同时完成。

6. **批量转写成本和队列**
   - 批量操作要提示预计数量、已完成跳过、失败可重试。

## 九、结论

Bayt 最值得 ListenWise 学的是：

- 搜索和发现优先于 RSS 输入。
- 搜索结果分节目和单集。
- 节目详情页用 shownotes 帮用户决定是否处理。
- 单集详情把字幕/简介/原文/中文组织清楚。
- 双语能力应成为播客场景的核心稿件能力。
- 常用操作需要直接外露。

Bayt 不适合 ListenWise 照搬的是：

- 播放器主流程。
- 中文音频生成。
- 声音克隆。
- 内容 feed 型首页。

ListenWise 更合适的方向是：

```text
发现内容 → 订阅节目或选择单集 → 手动获取文字稿 → 查看 shownotes/文字稿/AI 解读 → 导出到 Obsidian
```
