# 部署与分发

## 当前形态:Expo Go 内测(本期)

- **怎么用**:电脑跑 `npx expo start`,手机用 Expo Go 扫码即用(见《02-真机验收教程》)。
- **优点**:零安装包、零签名、改代码手机即时热更新,最适合现在「自己验证手感」。
- **局限**:
  - 依赖电脑上的开发服务器在线(关了就连不上);
  - 不是独立安装包,给别人用要对方也装 Expo Go 并扫你的码(同网络或用 `--tunnel`);
  - 用的是 Expo Go 这个壳,不能体现自定义 App 图标 / 启动页 / 原生模块。

**后端无需任何新部署**:移动端复用现有线上 Render 后端,你已经在跑的那套不用动。

---

## 进阶:要给别人装 / 要上架(Phase 1+,现在不用做)

当你验证完手感、决定往正式产品走,再做下面这些。这里只列路径,本期不执行。

### 生成独立安装包(EAS Build)

```bash
npm i -g eas-cli      # 一次性
eas login
cd apps/mobile
eas build -p android --profile preview   # 出 Android APK,可直接发给人装
eas build -p ios --profile preview       # 出 iOS 包,需 Apple 账号
```

- **Android**:APK 可直接 sideload 安装,门槛最低。
- **iOS**:需要 **Apple Developer 账号($99/年)**,通过 **TestFlight** 分发内测;装独立包必须签名。

### 上架商店(更靠后)

- iOS:App Store Connect 建 app → `eas submit -p ios` → 审核。
- Android:Google Play Console → `eas submit -p android` → 审核。
- 上架前**必须补**:正式账号体系(替换现在的临时口令)、多用户数据隔离、隐私政策、数据删除入口、用量/成本控制。这些在《00-总体方案》的 Phase 2–3 有清单。

---

## 一句话结论

现在:`npx expo start` + Expo Go 扫码,够你自己验证。
以后要正式:走 EAS Build → TestFlight / Play 内测 → 补账号与合规 → 上架。
