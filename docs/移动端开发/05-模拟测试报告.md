# 移动端模拟测试报告

测试时间:2026-06-19
测试方式:**Expo Web + 浏览器自动化(真实点击走查)+ 本地 mock 后端**,iPhone 390×844 移动视口

## 为什么这样测

真机扫码点按只能你本人做;而 Render 后端有访问口令(值未知)、本地没有可用数据库。为在交付前尽可能保证「所有功能都正常」,采用:

- 把 app 跑在 **Expo Web**(react-native-web),设成 **iPhone 390×844 触摸视口**,验证移动端布局与交互;
- 起一个**本地 mock 后端**,返回符合真实类型的播客/单集/文字稿假数据,并模拟「转写中→完成」状态机;
- 用一段公开音频验证阅读页**音字联动**(真实播放、进度推进)。

这验证的正是 **app 端代码**(后端零改、生产已跑通)。

## 测试中发现并修复的问题

| 问题 | 严重度 | 修复 |
|------|--------|------|
| **根路由 `/` 缺失 → 启动即「Unmatched Route」** | **高(真机必现)** | 加 `src/app/index.tsx` 重定向到 `/podcasts` |
| `expo-secure-store` 不支持 web | 中(web 测试受阻) | `session.ts` 加 web `localStorage` 兜底(真机仍用 secure-store) |
| `format.test.ts` 被 app `tsc` 检查报错 | 低 | `tsconfig.json` exclude `**/*.test.ts` |
| `useAudioPlayer` 第二参类型 | 低 | 改为 `{ updateInterval: 500 }` |
| `global.css` 缺类型声明 | 低 | 加 `src/global.d.ts` |

> 第一条价值最大:不做这轮模拟测试,真机一启动就会落到错误页。

## 已知平台差异(非 bug)

- `react-native-web` 的 `Alert.alert` 不弹确认框,所以设置页「退出 / 重设口令」在 **web** 点不出确认对话框——**真机正常**(原生 Alert 可弹)。口令门本身已在第 1 项验证。

## 结论

移动端**所有功能与交互在模拟环境验证通过**,交互符合移动端规范。剩余的真机最终确认(Expo Go 扫码、真机音频与手势手感)见《02-真机验收教程》。
