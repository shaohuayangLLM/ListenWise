# ListenWise 公网部署实战手册（可复用）

> 2026-06-04 实战完成。受控 Demo 形态：Vercel 前端 + Render 后端 + Supabase 数据库 + 阿里云 ASR/qwen。
> 本文 = 完整步骤 + **踩坑速查**（第四节是精华，照着避坑可省数小时）。
> 适用于任何「FastAPI + Postgres + Next.js」全栈应用部署到 Render/Supabase/Vercel。

---

## 一、上线信息与架构

| 项 | 值 |
|----|----|
| 前端（Vercel） | https://listen-wise.vercel.app |
| 后端（Render） | https://listenwise-api.onrender.com |
| 数据库 | Supabase Postgres（Singapore，Session pooler） |
| 访问口令 | 见 Render 环境变量 `ACCESS_PASSCODE`（不写入仓库） |
| 形态 | 受控 Demo（全站口令门，单用户模型） |

```
访客 → ainside.cn 主页入口卡片
   → Vercel 前端（Next.js，口令门，直连后端）
      → Render 后端（FastAPI，同进程后台任务转写，口令校验）
         → Supabase Postgres
         → 阿里云 Fun-ASR + qwen
```

关键设计：
- **转写不用 Celery/Redis**：改 FastAPI `BackgroundTasks` 同进程执行，Render 免费实例即可。
- **前端直连后端**：`NEXT_PUBLIC_API_BASE` 指向 Render，绕开 Vercel 代理体积限制；跨域靠后端 CORS。
- **访问口令**：后端中间件（`ACCESS_PASSCODE` 非空时 `/api`（除 health）需 `X-Access-Passcode` 头）+ 前端口令门。

## 三、部署步骤（实战顺序）

### 步骤 1 · Supabase 建库

1. 新建 project，区域选 **Singapore**，设数据库密码 → **建议纯字母数字**（避免 URL 编码坑，见坑 #3）。
2. 拿连接串：项目页**顶部** `Connect` 按钮（新版 UI 不在 Settings 侧栏）→ Connection string → **Session pooler**（端口 5432）。
3. 改成后端用的 `DATABASE_URL`：
   - `postgresql://` → **`postgresql+asyncpg://`**
   - 端口保持 **5432**（Session 模式，支持迁移；别用 6543 Transaction）
   - 最终：`postgresql+asyncpg://postgres.<ref>:<密码>@aws-x.pooler.supabase.com:5432/postgres`
4. 重置密码入口（新版藏得深）：直达 `https://supabase.com/dashboard/project/<项目ref>/settings/database`。

> 表结构无需手动建 —— Render 启动时 `alembic upgrade head` 自动建。

### 步骤 2 · Render 部署后端

1. Render → New → **Blueprint** → 选仓库 → 自动读 `render.yaml` 建 `listenwise-api`。
2. 填环境变量：
   | 变量 | 值 |
   |------|-----|
   | `DATABASE_URL` | 步骤 1 的 asyncpg 串 |
   | `DASHSCOPE_API_KEY` | 百炼 key（ASR + qwen 共用） |
   | `ASR_PROVIDER` | `fun_asr`（yaml 已写死） |
   | `APP_SECRET_KEY` | Render 自动生成（`generateValue`） |
   | `ACCESS_PASSCODE` | 自定义访问口令 |
   | `CORS_ORIGINS` | 先留空，步骤 3 拿到 Vercel 域名再回填 |
3. 看 Logs 确认：`Running upgrade -> ...`（迁移建表）+ `Application startup complete`。

### 步骤 3 · Vercel 部署前端

1. Vercel → Add New → Project → 导入仓库。
2. **Root Directory = `frontend`**（前后端同仓，必须指定！）。
3. 环境变量：`NEXT_PUBLIC_API_BASE` = `https://<render域名>/api`。
4. Deploy → 拿到前端域名。

### 步骤 4 · 回填 CORS

Render → Environment → `CORS_ORIGINS` = 前端域名（**无尾斜杠**，见坑 #7）→ 保存重新部署。

### 步骤 5 · 端到端验证

打开前端域名 → 口令门输 `ACCESS_PASSCODE` → 上传短音频/播客链接 → 看转写与摘要。

### 步骤 6 · 主页入口

`portfolio-2025/index.html` 已加 ListenWise 卡片，把 `VERCEL_URL_PLACEHOLDER` 换成真实域名 → `git push`（主页自动部署）。

## 四、踩坑速查 ⭐（本次实战全记录）

| # | 现象 | 根因 | 解法 |
|---|------|------|------|
| 1 | 构建用 Python 3.14、找不到 Database 设置 | Render 默认最新 Python；Supabase 新版 UI 改版 | 构建失败可设 `PYTHON_VERSION=3.12.0`；连接串走顶部 `Connect` 按钮，重置密码用直达 URL `/project/<ref>/settings/database` |
| 2 | 运行时 `asyncpg ConnectionRefused`，但迁移能连 | 连接串密码/格式解析错位（非网络） | 核对 `DATABASE_URL` host/port/密码；用 asyncpg 驱动、Session pooler 5432 |
| 3 | 密码含 `#` → 连接串被截断、解析错乱 | `#` 是 URL fragment 分隔符 | 编码成 `%23`；**最佳实践：数据库密码只用字母数字** |
| 4 | 启动崩 `ValueError: invalid interpolation syntax` | alembic 的 configparser 把密码里 `%` 当插值语法 | `env.py` 绕过 `config.set_main_option`，直接 `create_engine(sync_url)`（已修，见 `alembic/env.py`） |
| 5 | `FATAL: password authentication failed` | Supabase 真实密码 ≠ `DATABASE_URL` 里的密码 | 在 Supabase **重置**密码，两边用同一个（纯字母数字） |
| 6 | `CORS_ORIGINS` 填了仍跨域失败 | 值带了尾斜杠 `/` | 去掉尾斜杠，精确匹配浏览器 Origin |
| 7 | 前端口令门「口令不正确」 | CORS 没放行 → 前端验证口令的请求被拦 → 误判口令错 | 回填 `CORS_ORIGINS` 为前端域名并重新部署 |
| 8 | 前端「Network Error」，后端其实 500 | Starlette 默认 500 在 CORS 中间件外层生成、**不带 CORS 头**，被浏览器吞成 Network Error | 加全局异常处理器补 CORS 头 + 回传错误类型（已加，见 `main.py`） |
| 9 | 上传/播客 500 `ForeignKeyViolationError` | 代码硬编码 `user_id=1`，全新库 `users` 表为空 | 加幂等种子迁移插入默认用户（已加，见迁移 `e6f2a4b9c1d8`） |

**经验提炼**：
- 连接串编码问题占了一半的坑（`#`/`%`/尾斜杠）→ **数据库密码用纯字母数字、连接串复制粘贴别手敲**，一次避开。
- 「Network Error / Internal Server Error」是症状不是病 → 先加异常处理器**把真实错误暴露出来**，再对症修，比反复翻日志快得多。
- 全新数据库 vs 本地老库的差异（种子数据、已存在的 user）是最隐蔽的坑 → 种子数据要进迁移。

## 六、已知取舍与待优化

- **音频持久化（M11 已做）**：转写完成后把本地音频转存 Supabase Storage（`file_url` 变 public URL），部署/重启不再丢。⚠️ **Supabase Free 对象存储仅 1 GB**（≈16 小时 mp3）+ 月流量 5 GB；多人多次上传长音频会逼近上限，在 Supabase Usage 页监控。满了：清理旧音频 / 升级 Pro（$25/月 100GB）/ 换阿里云 OSS。**删记录时 Supabase 文件不会自动删**，需定时清理。
- **单用户模型**：进口令门的人共享同一份记录列表。要每人独立需做账号体系。
- **异常处理器暴露错误详情**：调试期返回 `str(exc)` 给前端，上线稳定后应收敛为笼统提示（保留 CORS 头修复）。
- **Render 免费实例休眠**：闲置后首次访问冷启动 ~50s。
- **数据库密码安全**：调试中密码曾出现在对话/日志，建议稳定后在 Supabase 重置一次。
