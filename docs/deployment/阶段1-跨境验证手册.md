# 阶段① 跨境验证操作手册

> 目标：在 Render（海外）实测一次真实 Fun-ASR 转写的**延迟与成功率**，判定后端能否落在海外。
> 这是 go/no-go 判定点 —— 通过才继续做完整部署，不通过则后端转国内。
>
> 分工：代码与配置已就绪（`render.yaml` + 诊断端点 `/api/diag/transcribe`）；下面的控制台操作需你在自己的 Render 账号里完成。

---

## 前置

- 代码已 push 到 GitHub：`shaohuayangLLM/ListenWise`（含 `render.yaml`）。
- 准备一个**短音频**做测试：建议 **1–2 分钟、几 MB** 的 mp3/m4a/wav。
  - ⚠️ 不要用长音频：Render 免费实例同步请求时间过长可能被断开。验证只需短音频证明链路通。
  - 音频内容随意（中文最好，能顺便看转写质量）。

---

## 步骤 1：在 Render 创建服务（Blueprint 方式，最省事）

1. 登录 Render → **New** → **Blueprint**。
2. 连接 GitHub，选仓库 `shaohuayangLLM/ListenWise`。
3. Render 读到根目录 `render.yaml`，自动识别出一个名为 `listenwise-api` 的 web 服务。
4. 在创建界面填写标记为 `sync: false` 的两个环境变量：
   - `DASHSCOPE_API_KEY` = 你的百炼 key
   - `DIAG_TOKEN` = 自定义一个口令（如 `lw-verify-2026`，调诊断端点要用）
   - （`ASR_PROVIDER=fun_asr` 已在 yaml 里写死，无需填）
5. 点 **Apply / Create**，等待构建 + 部署（首次约几分钟）。

> 若 Blueprint 不识别，可改手动：New → Web Service → 选仓库 → **Root Directory 填 `backend`** → Build `pip install -e .` → Start `uvicorn app.main:app --host 0.0.0.0 --port $PORT` → 配上面 3 个环境变量。
> 若构建因 Python 版本失败：在环境变量加 `PYTHON_VERSION` = `3.12.0`。

部署成功后你会得到一个地址，形如 `https://listenwise-api.onrender.com`。

---

## 步骤 2：先唤醒（免费实例会休眠）

```bash
curl https://listenwise-api.onrender.com/api/health
```

返回 `{"status":"ok","app":"ListenWise"}` 即服务已起。第一次可能等十几秒（冷启动）。

---

## 步骤 3：跑真实转写验证

把 `<你的地址>`、`<DIAG_TOKEN>`、`<音频文件>` 换成实际值：

```bash
curl -X POST "https://listenwise-api.onrender.com/api/diag/transcribe" \
  -H "X-Diag-Token: <DIAG_TOKEN>" \
  -F "file=@<音频文件路径>"
```

成功返回示例：

```json
{
  "success": true,
  "provider": "fun_asr",
  "model": "fun-asr",
  "file_size_mb": 2.3,
  "total_sec": 28.6,
  "word_count": 412,
  "segment_count": 18,
  "sample": "这里是转写出来的前 120 字……"
}
```

失败返回会带 `"success": false` 和 `error` 字段（如超时、连接失败）。

---

## 步骤 4：多跑几次，记录结果

唤醒后连续跑 **3–5 次**（避开冷启动那次），记录每次的 `total_sec` 和 `success`。

判定标准：

| 结果 | 结论 |
|------|------|
| 短音频稳定 `success: true`，耗时合理（几十秒内） | ✅ **通过** → 海外 Render 可行，进入阶段②完整部署 |
| 频繁 `success: false`（超时/连接失败），或耗时极长/波动剧烈 | ❌ **不通过** → 后端转国内部署点（阿里云函数计算/腾讯云/Zeabur 国内） |

把几次的耗时和成功率发我，我帮你判定并决定阶段②走哪条路。

---

## 安全说明

- 诊断端点用 `DIAG_TOKEN` 保护，没有口令无法调用，避免被陌生人刷你的 ASR 额度。
- 此端点是**临时**的，仅为验证。阶段② 会删除它，换成正式的访问口令鉴权 + 完整链路。
- `DASHSCOPE_API_KEY` 只存在 Render 环境变量里（不进仓库）。
