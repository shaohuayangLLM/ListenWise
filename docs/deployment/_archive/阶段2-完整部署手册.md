# 阶段② 完整部署操作手册（受控 Demo）

> 目标：把 ListenWise 作为「受控 Demo」上线 —— 访问口令保护，前端 Vercel + 后端 Render + 数据库 Supabase，挂到 `ainside.cn` 下方入口。
>
> 代码已全部就绪并本地验证。下面是**需要你在控制台操作的步骤**（我无法替你登录账号）。按顺序做，每步完成再下一步。

---

## 架构总览

```
访客 → ainside.cn 主页入口卡片
        → Vercel 前端（Next.js，口令门）
            → Render 后端（FastAPI，同进程转写，口令校验）
                → Supabase Postgres（数据）
                → 阿里云 Fun-ASR + qwen（转写/摘要）
```

- 转写改为 FastAPI 后台任务，**不需要 Redis/Celery**（Render 免费实例够用）。
- 上传音频存 Render 临时盘 → 转写完成。⚠️ Render 重启后上传的原音频会丢失（详情页对上传记录的音频回放会失效，文字稿/摘要不受影响）。播客是外链音频，不受影响。这是受控 Demo 的已知取舍，后续可接对象存储解决。

## 步骤 1：Supabase 建库

1. https://supabase.com → 新建 project（区域选离 Render 近的，如 Singapore），设一个数据库密码（记下）。
2. 项目建好后 → 左下 **Project Settings** → **Database** → 找 **Connection string** → 选 **URI**。
3. 复制那条连接串，形如：
   `postgresql://postgres.xxxx:[YOUR-PASSWORD]@aws-0-xxx.pooler.supabase.com:5432/postgres`
4. **改两处**，得到给 Render 用的 `DATABASE_URL`：
   - 开头 `postgresql://` → 改成 `postgresql+asyncpg://`
   - `[YOUR-PASSWORD]` → 换成你刚设的真实密码
   - 端口用 **5432**（session 模式，支持迁移）；不要用 6543
   - 最终形如：`postgresql+asyncpg://postgres.xxxx:真实密码@aws-0-xxx.pooler.supabase.com:5432/postgres`

> 表结构不用手动建 —— Render 启动时会自动跑 `alembic upgrade head` 创建。

---

## 步骤 2：更新 Render 后端

你阶段①已经建好 `listenwise-api` 服务。现在代码已 push（含新的 `render.yaml`），Render 会自动重新部署。你只需补环境变量：

1. Render → 进 `listenwise-api` → **Environment**。
2. 确认/添加这几个变量：
   | 变量 | 值 |
   |------|-----|
   | `DATABASE_URL` | 步骤 1 得到的 asyncpg 连接串 |
   | `DASHSCOPE_API_KEY` | 你的百炼 key（阶段①已填） |
   | `ASR_PROVIDER` | `fun_asr`（yaml 已写死，无需手填） |
   | `APP_SECRET_KEY` | Render 自动生成（render.yaml 里 `generateValue`，不用管） |
   | `ACCESS_PASSCODE` | 自定义访问口令，发给受邀用户（如 `listen2026`） |
   | `CORS_ORIGINS` | **先留空或填占位**，步骤 3 拿到 Vercel 域名后再回填 |
3. 旧的 `DIAG_TOKEN` 可以删掉（诊断端点已随代码移除）。
4. 保存后 Render 会重新部署。看 **Logs**：应出现 `alembic upgrade head` 成功 + `Uvicorn running`。
   - 若迁移报 `prepared statement` 相关错误（asyncpg + pooler 偶发）→ 告诉我，我加一行 `statement_cache_size=0` 处理。

部署完成后地址仍是 `https://listenwise-api.onrender.com`。

---

## 步骤 3：Vercel 部署前端

1. https://vercel.com → **Add New** → **Project** → 导入仓库 `shaohuayangLLM/ListenWise`。
2. 关键设置：
   - **Root Directory** = `frontend`（重要！仓库是前后端同仓，必须指到 frontend）
   - Framework 会自动识别 Next.js
3. 展开 **Environment Variables**，加一个：
   - `NEXT_PUBLIC_API_BASE` = `https://listenwise-api.onrender.com/api`
4. **Deploy**。完成后拿到前端域名，如 `https://listenwise-xxx.vercel.app`。

---

## 步骤 4：回填 Render 的 CORS

1. 回到 Render → `listenwise-api` → Environment → 把 `CORS_ORIGINS` 填成步骤 3 的 Vercel 域名：
   `https://listenwise-xxx.vercel.app`（如有多个域名用逗号分隔）
2. 保存 → 等重新部署。

> 这步是让后端允许前端跨域调用。不填的话前端会报 CORS 错。

---

## 步骤 5：验证端到端

打开 Vercel 域名 `https://listenwise-xxx.vercel.app`：

1. 应看到**口令门** → 输入步骤 2 设的 `ACCESS_PASSCODE` → 进入。
2. 传一个短音频 → 等转写 → 看逐字稿。
3. 试播客链接转写（小宇宙单集）→ 看摘要时间线。
4. 试导出、收藏、重命名、删除。

有任何一步不对，把现象发我。

## 步骤 6：主页 ainside.cn 加入口

我已在 `个人生活/portfolio-2025/index.html` 准备好入口卡片（指向你的 Vercel 域名）。你只需：

1. 打开 `portfolio-2025/index.html`，把卡片里的 `VERCEL_URL_PLACEHOLDER` 换成真实 Vercel 域名（搜这个词就能找到）。
2. 在 `portfolio-2025` 目录 `git add -A && git commit && git push` → Vercel 自动部署主页。

> 入口卡片的具体位置和样式见步骤 6 完成后的说明。

## 上线后注意

- **成本**：受控 Demo 有口令保护，正常不会被刷。但 ASR/qwen 按量计费，留意账单。
- **音频持久化**：上传的原音频在 Render 重启后丢失（见架构总览）。若要长期保留回放，需接对象存储，作为后续。
- **数据隔离**：当前仍是单用户模型（所有进入口令门的人共享同一份记录列表）。受控 Demo 可接受；若要每人独立数据，需做账号体系（后续）。
